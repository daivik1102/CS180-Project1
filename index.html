1. Approach

Each grayscale scan is converted to floating point using its original integer dtype range, then divided into blue, green, and red exposures. Green and red are translated independently into the blue coordinate system. The final image is stacked in RGB order.

Offsets below are applied shifts in (x,y) order: positive x moves right and positive y moves down. Internally, array operations use (dy,dx). If an input height is not divisible by three, only the final one or two leftover rows are discarded.

Matching metric

For corresponding pixel vectors a and b, the score is NCC = sum((a-mean(a))*(b-mean(b))) / sqrt(sum((a-mean(a))²)*sum((b-mean(b))²)). The translation with the largest score is selected. Mean subtraction handles additive brightness shifts; normalization handles positive multiplicative changes. It does not make arbitrary cross-channel appearance changes disappear.

Scores use every pixel in a common interior rectangle. Ten percent of each image dimension is excluded at the scoring borders; the rectangle is reduced further when needed so all candidate translations have valid support. Thus every candidate in one search is evaluated using the same reference pixels, without circular wraparound.

2. Single-scale alignment

The low-resolution JPEGs are searched exhaustively over [-15,15] pixels in both directions. These results use raw intensities and NCC; no pyramid or edge representation is used.

3. Coarse-to-fine raw-pixel baseline

A pyramid is built explicitly by separable convolution with [1,4,6,4,1]/16, followed by retaining every second row and column. Reduction stops when the largest dimension is at most 256 pixels. The coarsest level searches ±15 pixels. Each finer level doubles the previous shift and searches a ±2-pixel neighborhood.

The final search operates at the original input resolution. All baseline scores below use raw channel intensities, not edges. The same parameters are used for every photograph. Numba compiles the explicitly implemented scoring loops; it does not supply an alignment or pyramid algorithm.

After shifting, only the common non-wrapped support is retained. This is geometric overlap cropping, not an automatic detector of the original photographic borders. Full-resolution outputs are saved separately; webpage previews are resized only after alignment.

4. Additional collection examples

Three additional original glass negatives were downloaded from the Library of Congress and processed with the same raw-pixel NCC pyramid, without image-specific parameters.

5. Extension: gradient-based alignment

The extension replaces each level's raw intensities with Sobel gradient magnitude, sqrt(gx²+gy²), then runs the same NCC search. Structural boundaries can agree even when their absolute channel intensities differ. However, colored edges, motion, and repetitive texture can still produce incorrect matches.

The comparisons below select the four largest disagreements between raw and edge offsets. Disagreement is a review cue, not proof of an improvement. The captions report the actual visual-review decisions.

7. Failures, observations, and limitations

Visual review is pending.

A global translation cannot fix object motion, rotation, scale differences, or damaged portions of a plate. Raw NCC can also be confused when a colorful object changes its relative brightness across exposures—for example, the Emir's clothing. This is a possible failure mechanism, not a claim that a specific image failed in this run. Image-specific findings appear above.

Numerical NCC values are optimization scores, not ground-truth accuracy measurements. The synthetic tests check implementation invariants; real-image correctness additionally requires inspection.
